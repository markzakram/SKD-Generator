# JadiASN SKD Studio v2.2

## Soal TWK dan TKP baru tanpa API

**Opsi TWK v2:** redaksi tindakan dan pilihan bacaan telah disunting agar panjangnya sebanding. Generator memeriksa seluruh opsi (maksimal selisih 4 kata dan rasio karakter terpanjang/terpendek 1,5), tanpa menetapkan bahwa kunci harus pendek atau panjang. Uji `npm run verify:twk-options` memeriksa 132 variasi lokal dan 100 seed pada masing-masing profil bebas/tryout, termasuk keberhasilan tebakan berdasarkan panjang kata/karakter. Bank contoh tetap memakai redaksi sumber. Paket baru dan penggantian nomor memakai v2; paket v1 yang sudah tersimpan tetap dapat dibuka dan diperiksa dengan model asalnya.

Pada **Buat paket → 3 Sumber, jumlah, dan kesulitan**, pilih **Soal baru · generator lokal** untuk TWK dan/atau TKP. Pilihan ini tersedia dalam profil tryout maupun latihan bebas. Instalasi baru memilih mode baru; pengaturan pengguna lama dan paket yang tersimpan tetap dipertahankan. Pilih **Gunakan bank contoh** untuk memakai sumber sebelumnya.

Mesin lokal menyusun stimulus, pilihan, kunci, poin, pembahasan, dan cara cepat dari **konteks + kondisi penentu + model keputusan**. Tidak memerlukan API key, biaya per soal, atau server AI. Contohnya, aduan belum terverifikasi membutuhkan pemeriksaan; kesalahan yang sudah terbukti dan berada dalam kewenangan membutuhkan koreksi; keputusan di luar kewenangan membutuhkan eskalasi. Kondisi yang berubah benar-benar mengubah tindakan terbaik serta alasan pilihan, bukan hanya nama tokoh.

- **TWK:** 12 model penerapan nilai pada Nasionalisme, Integritas, Bela Negara, Pilar Negara; 6 model Bahasa Negara sesuai mapping (ide pokok, simpulan, kalimat efektif, kata baku, tanda baca, EYD).
- **TKP:** 18 model pada seluruh enam kompetensi. Setiap model mempunyai 3 kondisi keputusan dan 3 konteks pekerjaan. Skor 1–5 disertai alasan setiap opsi, pembeda 5 vs 4, dan rubrik penelaahan.
- **Kapasitas saat ini:** 132 kombinasi TWK dan 202 kombinasi TKP dalam 78 model. Angka ini menghitung kombinasi kondisi dan konteks; beberapa memakai prinsip keputusan yang sama. Pengacakan opsi tidak menambah kapasitas. Tiga paket lengkap dapat memakai TWK/TKP baru tanpa isi identik, dengan kesulitan campuran. Kapasitas berkurang ketika difilter menurut chapter/kesulitan. Generator menolak kelebihan kapasitas sebelum mulai; pemakaian ulang dapat diizinkan antarpaket.
- **Pustaka soal → Model generator soal baru:** pratinjau setiap model; ubah konteks dan kondisi untuk membandingkan keputusan serta pembahasannya.
- **Pemeriksaan:** hasil perlu diperiksa pengguna. Pemeriksaan model memastikan konsistensi teks, opsi, kunci, dan skor terhadap parameter penyusun; bukan pembuktian independen atas kualitas akademik atau kalibrasi kesulitan. Menyunting konten membatalkan bukti model (dan, bila fitur kurasi dihidupkan, persetujuan sebelumnya; lihat Fitur telaah dan kurasi).
- **Kompatibilitas:** penggantian mempertahankan mode baru, chapter, dan kesulitan. Cadangan, penyalinan, PDF/Word/CSV/JSON, serta uji peserta menggunakan alur yang sama. Mapping 30/35/45 tetap berlaku. TIU masih mengikuti sumber/model TIU yang tersedia.

Implementasi: `lib/local/{schema,twk,tkp,bahasa,index}.ts`. Tambahkan model dan verifikasi kapasitas untuk memperluas variasi; hasilnya tidak diklaim sebagai generasi bahasa tanpa batas. Acuan prinsip dan ejaan diperiksa pada [UUD NRI 1945 — JDIH DPR](https://jdih.dpr.go.id/index/uu1945), [EYD V — Badan Bahasa](https://ejaan.kemendikdasmen.go.id/), serta [KBBI Daring](https://kbbi.kemendikdasmen.go.id/). Aturan operasional pada kasus yang menyebut pedoman internal merupakan fakta simulasi pada stimulus, bukan klaim peraturan baru.

Verifikasi: `npm run verify:local` mencakup seluruh kombinasi, pengacakan, perubahan keputusan saat kondisi berubah, penolakan isi yang diubah tanpa kurasi, tiga paket unik, sumber campuran, kapasitas, cadangan, dan penggantian. `scripts/browser-local.mjs` memeriksa alur browser dan ekspor.

API menerima `twkSource: "new"` dan `tkpSource: "new"`. Nilai `"accepted"` atau kolom yang tidak dikirim mempertahankan perilaku bank sebelumnya. Pilihan awal di halaman generator: profil Standar tryout 2027, Penyusunan TWK = soal baru (generator lokal), Penyusunan TKP = bank. Pada profil tryout, "bank" TKP berarti 144 kasus orisinal di data/tkp-kasus/ (label pilihannya "Bank kasus orisinal"; keputusan QC akademik #2, 3 Nov 2026): 135 contoh tryout TKP tetap tersimpan di data/tryout-reference.json tetapi tidak dipilih karena identik dengan dokumen acuan tim. Kuota per bab mengikuti mapping (8/8/8/7/7/7), jadi tanpa pengulangan antarpaket cukup untuk 3 paket. Kasus orisinal dan 26 contoh panduan TKP juga dipakai pada Latihan bebas (label pilihannya "Bank (kasus baru + contoh)"), CLI (`npm run generate`), dan API tanpa profil. Jalur lokal TKP tetap ada dan dapat dipilih manual di form atau lewat `tkpSource: "new"` / `--tkp new`. CLI memakai bank untuk TWK dan TKP kecuali `--twk new` / `--tkp new` diberikan. Pengaturan tersimpan di peramban diberi nomor versi: preferensi lama dengan `tkpSource: "new"` (bawaan lama) diganti sekali ke bank, pengaturan lain tidak berubah (lib/prefs.ts).

~~~powershell
npm run generate -- --profile tryout-2027 --twk new --tkp new --paket 3
~~~

## Acuan tiga tryout 2027

Profil **Standar tryout 2027** pada halaman generator memakai **Mapping SKD 2027.xlsx** dan 312 contoh yang dinyatakan layak oleh pengguna: 90 TWK, 87 TIU, dan 135 TKP. Pilih **Latihan bebas** untuk pengaturan kuota manual sebelumnya.

### Jumlah per chapter

Pada panel **Kuota per chapter**, tombol **Atur jumlah sendiri** membuka isian per chapter (dikelompokkan Subtes > Category > Lesson, dengan kolom cari dan maksimum tiap chapter). Kartu **Latihan bebas** punya pintasan ke isian yang sama. Isian dimulai dari saran mapping bila dibuka dari panel, kosong bila dibuka dari pintasan; **Kembalikan saran mapping** menutupnya kembali. Hasilnya tetap jalur standar tryout 2027: sumber per baris, pembangkit, label, format pembahasan, dan `mappingId` sama. Jumlah soal, jenis paket, dan durasi (sebanding jumlah soal) mengikuti isian, urutan soal mengikuti baris mapping. Tanpa isian, kuota dan hasilnya tetap seperti sebelumnya.

Semua 57 chapter bisa dipilih, tetapi tiap chapter punya maksimum per paket. Bila soal tidak boleh sama antarpaket, stok dibagi jumlah paket. Kesulitan yang dipilih ikut membatasi. Contoh pada bawaan satu paket: Logika Pernyataan 3 (hanya contoh, belum ada pembangkit), kasus TKP orisinal 21–26 per kompetensi, dan chapter numerik berbasis contoh 1–6; pilih **Variasi TIU terhitung** untuk chapter numerik yang punya pembangkit. Deret Angka - Hijab dan Template belum punya contoh maupun pembangkit, jadi maksimumnya 0. Silogisme (baris 13–15) selalu lewat generator blueprint: contoh blueprint lebih dulu, lalu pembangkit, dengan keluarga modus berputar merata.

API dan CLI: `chapterCounts` pada `POST /api/generate` (misalnya `{"chapterCounts":{"map-14":15}}`) dan `--chapter map-14=15` pada `npm run generate` (boleh diulang atau dipisah koma). Id chapter ada di `data/skd-mapping.json`.


Pada paket penuh 110 soal, distribusi mengikuti 37 baris berkuota dari workbook: 30 TWK, 35 TIU, 45 TKP. Seluruh 57 chapter tetap tersedia dalam data mapping, termasuk chapter latihan yang tidak memiliki kuota pada tryout penuh.

- TWK: Nasionalisme, Integritas, Bela Negara, dan Pilar Negara masing-masing 6 soal; Bahasa Negara 6 soal, masing-masing satu ide pokok, simpulan, kalimat efektif, kata baku, tanda baca, dan EYD.
- TIU verbal: silogisme 5 (1 tiga premis, 2 narasi dua premis, 2 narasi tiga premis), analogi kata 1, argumen 3, susunan/posisi 2.
- TIU numerik: berhitung 3, kecukupan data 6, deret 1, matriks angka 2, pola tabel 2, kombinasi pernyataan 1, kombinasi optimal 1.
- TIU figural: analogi, ketidaksamaan, serial, dan matriks masing-masing 2.
- TKP: Pelayanan Publik, Jejaring Kerja, Sosial Budaya masing-masing 8; TIK, Profesionalisme, Anti Radikalisme masing-masing 7.

Rotasi tiga paket pada bagian bawah sheet **3 TO 0 Latsol** diterapkan pada pasangan chapter aljabar, jenis/sifat-keterbagian-faktor bilangan, serta tiga kelompok soal cerita. Sel yang kosong pada kuota tryout tidak diubah menjadi kuota 1. Angka ketersediaan SIADU dalam workbook tidak dianggap sebagai soal yang telah tersedia di proyek.

**Penyusunan TIU** menyediakan dua pilihan:

1. **Utamakan contoh diterima:** mempertahankan stimulus, urutan pilihan, kunci, skor, dan pembahasan teks dari dokumen. Tiga paket penuh dapat disusun tanpa soal identik; sebanyak 300 soal berasal dari contoh, sedangkan 30 lainnya memakai pola analogi/figural dan pelengkap susunan. Contoh analogi kata dan figural tidak terdapat pada berkas baru yang disertakan, sehingga bagian itu memakai mesin proyek yang tersedia.
2. **Variasi TIU terhitung + contoh acuan:** membuat variasi pada model silogisme, susunan, pecahan, perkalian/pembagian setara, aljabar terbatas, deret, matriks/tabel, kombinasi, dan figural. Sifat/keterbagian bilangan serta rotasi cerita khusus tetap menggunakan contoh diterima; Susunan & Posisi dan Memperkuat/Memperlemah Argumen memakai pembangkit khusus (lihat "Verbal Analitis menurut Panduan Produksi Soal TIU JadiASN"). Pilihan TIU independen dari pilihan sumber TWK dan TKP di atasnya.

Variasi baru diberi label tersendiri dan diperiksa ulang melalui model. Aljabar variasi memakai domain bilangan bulat yang dinyatakan eksplisit pada soal; tidak diperlakukan sebagai pembuktian untuk semua bilangan real. Contoh sumber dengan label HOTS tetap menyimpan label tersebut pada metadata; estimasi kesulitan aplikasi menjadi sulit, bukan klaim kalibrasi empiris.

**Pustaka soal → Acuan tryout diterima** memuat semua 312 contoh, termasuk chapter tambahan yang tidak masuk paket penuh. Sumber menampilkan nama berkas dan nomor soal. Teks cara cepat ikut ditampilkan, disalin, serta diekspor ke PDF, Word, PNG, dan CSV. Rumus Word diekstrak sebagai teks matematis; pecahan campuran ditulis dengan tanda tambah eksplisit agar tidak terbaca sebagai perkalian. Tabel dipertahankan. Diagram bantu yang berada dalam pembahasan sumber tidak direplikasi; uraian langkah dan tabelnya tetap digunakan.

Versi awal **Dhea_TWK - Bahasa Negara.docx** tidak dihitung ulang; versi **Done Input** menjadi sumber kanonisnya. Penanda sumber adalah **Contoh diterima**, **Variasi baru**, atau **Adaptasi sumber** setelah konten disunting. Semua paket tetap perlu diperiksa pengguna. Satu catatan ketidaksesuaian alasan opsi D pada sumber Nynda TKP soal 1 ditampilkan dalam panel mutu tanpa mengubah poin asli diam-diam.

Data dan verifikasi:

- **data/skd-mapping.json**: kuota, category, lesson, chapter, baris asal, dan rotasi workbook.
- **data/tryout-reference.json**: contoh, metadata sumber, label asli, nomor soal, dan hash dokumen.
- **data/tryout-import-report.json**: jumlah impor, versi duplikat, dan perubahan notasi.
- **scripts/extract-tryouts.py**, kemudian **scripts/import-tryouts.py**: impor ulang dari berkas asli di G:/Downloads; ekstraksi workbook memerlukan openpyxl. Python tidak diperlukan saat build atau runtime Vercel.
- **npm run verify:tryout**: memeriksa sumber, rotasi dan kuota tiga paket, duplikasi, variasi pada banyak seed, notasi/kunci hitungan sumber, penggantian soal, cara cepat, dan cadangan.
- **scripts/browser-tryout.mjs**: menguji profil, tiga paket, pustaka, variasi TIU, ekspor Word/PDF/CSV, pemulihan browser, API, dan ukuran mobile.

Pada mode bank contoh, profil ini menolak permintaan ketika contoh suatu chapter habis; tidak mengisi kuotanya dengan materi generik. Untuk memakai ulang sumber di paket berbeda, matikan larangan pengulangan antarpaket. Jumlah soal selain 110 diskalakan menurut rasio subtes dan chapter; jumlah sangat kecil dapat membuat beberapa chapter mendapat kuota nol.

Ruang kerja untuk menyusun, menelaah, menguji, dan mengekspor paket latihan TWK, TIU, TKP, atau SKD gabungan. Tampilan menggunakan biru #3D6E99, biru tua #052C5F, dan emas #E8B41E dari identitas JadiASN.

Generator dan ekspor berjalan di browser. Aplikasi tidak memerlukan API key atau layanan basis data eksternal. Paket, versi, dan hasil peserta tersimpan dengan IndexedDB di browser yang digunakan.

## Menjalankan dan deploy

Memerlukan Node.js ≥20.9. Gunakan Node.js 22 atau 24 untuk deployment.

~~~powershell
npm install
npm run dev
~~~

Buka http://localhost:3000. Pilih **Buat paket** untuk menyusun latihan pertama. Jika sudah ada paket tersimpan, aplikasi membuka Hasil paket terakhir.

~~~powershell
npm run verify
npm run verify:quality
npm run typecheck
npm run build
npm start
~~~

**npm run build** butuh koneksi internet karena font Manrope dan DM Sans diunduh dari Google Fonts saat build (next/font), lalu disajikan dari aplikasi sendiri.

Untuk Vercel:

1. Masukkan proyek ke repositori GitHub dan impor sebagai proyek Vercel.
2. Framework: **Next.js**. Root Directory: folder proyek ini; bila repositorinya khusus proyek ini, gunakan root repositori.
3. Install: **npm install**. Build: **npm run build**. Output Directory: bawaan Next.js.
4. Gunakan Node.js 22.x atau 24.x. Environment variable wajib: **SITE_PASSWORD** (password gerbang situs di `proxy.ts`), untuk Production dan Preview. Bila kosong, situs di Vercel menjawab 503. Browser meminta nama pengguna dan password; nama pengguna boleh apa saja. Setelah nilainya diubah, lakukan redeploy. Di komputer lokal tanpa variabel ini tidak ada gerbang.
5. Sertakan **data/**, **package-lock.json**, dan seluruh kode aplikasi. Folder references/, output/, dan test-results/ tidak diperlukan di deployment.

Konfigurasi tersedia pada vercel.json. Dokumentasi: [Next.js di Vercel](https://vercel.com/docs/frameworks/full-stack/nextjs).

Next.js telah diperbarui ke 16.3.8. Setelah memasang dependensi baru, restart server dev yang masih memakai versi sebelumnya. Pemeriksaan npm audit dilakukan terpisah dari pengujian aplikasi.

## Alur penggunaan

1. **Buat paket:** formulir dibagi menjadi blok bernomor 1–3 (acuan penyusunan; jenis paket dan materi; sumber, jumlah soal, dan kesulitan). Pengaturan lanjutan memuat jumlah paket, durasi, seed, hindari soal sama, dan submateri khusus.
2. **Blueprint:** tinjau ringkasan blueprint di kanan (menempel di layar lebar; di layar sempit tombol tetap di bawah layar): jumlah soal, komposisi TWK/TIU/TKP, rincian per subtes, dan cek persediaan. Persentase kesulitan dapat ditentukan sendiri; kuota dapat disunting secara manual pada tabel di bawah formulir. Persediaan yang kurang menghasilkan pesan kesalahan, tanpa penggantian materi diam-diam.
3. **Hasil paket:** setelah **Buat paket**, pengguna langsung masuk ke sini. Daftar soal (satu daftar bergulir; cari nomor atau teks, filter subtes) ada di kiri, soal beserta kunci dan pembahasan di tengah, dan mutu otomatis di kanan sebagai informasi (tanpa tombol keputusan). Di layar lebar ketiganya tampil berdampingan tanpa menggulir halaman. Pintasan papan ketik: **J**/**K** soal berikutnya/sebelumnya dalam hasil filter; pintasan tidak aktif saat mengetik atau saat dialog terbuka. **Tampilan peserta** menyembunyikan kunci dan pembahasan. Panel **Ambil soal** di atas kartu soal menyalin atau mengunduh soal itu saja, atau beberapa soal terpilih (lihat bagian Ambil soal satuan atau terpilih).
4. **Sunting dan ganti nomor:** **Sunting soal** membuat revisi baru dan membatalkan bukti model soal itu. **Ganti nomor ini** mengganti nomor yang sedang dibuka. Untuk banyak nomor, centang kotak di tiap baris daftar soal (pilihan cepat **Pilih semua** dan **Kosongkan**), lalu tekan **Ganti nomor terpilih (n)**. Penggantian berjalan berurutan menurut nomor: pengganti berasal dari chapter (atau materi, pada latihan bebas), subtes, dan tingkat yang sama, serta tidak kembar dengan soal lain di semua paket maupun dengan pengganti lain pada aksi yang sama. Nomor dan urutan soal tidak berubah. Nomor yang stoknya habis tetap soal semula dan dilaporkan beserta alasannya; ringkasannya berbunyi, misalnya, "3 nomor diganti". Satu aksi menjadi satu versi baru yang tersimpan di IndexedDB dan bisa dipulihkan dari Riwayat paket. Logikanya di `lib/replace.ts`.
5. **Periksa sendiri:** aplikasi tidak memberi status persetujuan; kebenaran kunci, pengecoh, dan pembahasan diperiksa pengguna. Soal dengan kegagalan struktur/skor tetap menahan ekspor.
6. **Evaluasi peserta:** uji semua soal paket (bila fitur kurasi dihidupkan: hanya soal yang disetujui), periksa respons, kemudian gunakan hasilnya untuk revisi berikutnya.
7. **Ekspor:** semua soal paket diekspor tanpa label draf dan nomor diurutkan kembali. Pilihan cakupan draf/disetujui hanya muncul bila fitur kurasi dihidupkan.

### Fitur telaah dan kurasi (disembunyikan)

Persetujuan per soal, status **Draf → Perlu revisi → Disetujui**, isian dan catatan penelaah, **Keluarkan dari paket**, filter status, ringkasan "x/110 disetujui", pintasan **A**/**R**, pilihan cakupan ekspor, dan label "DRAF KURASI" pada ekspor disembunyikan pada v2 atas keputusan pengguna (membuat paket lalu QC sendiri). Semuanya bergantung pada satu saklar, `KURASI_AKTIF` di `lib/config.ts` (sekarang `false`); mengubahnya menjadi `true` mengembalikan tab **Ruang kurasi**, tombol **Buat paket untuk dikurasi**, dan seluruh alur telaah seperti semula. Kode, fungsi (`setReview`, `exportPackages`, dan lainnya), serta data `review` pada workspace tidak dihapus: workspace lama tetap dimuat, dicadangkan, dan diekspor. Saat saklar mati, soal yang pernah ditandai dikeluarkan pada workspace lama tetap dilewati saat ekspor dan uji peserta (ditandai "Dikeluarkan" di daftar), tetapi bisa diganti lewat **Ganti nomor**. Saat saklar hidup, syarat persetujuan berlaku seperti semula (identitas penelaah, konfirmasi pemeriksaan, catatan untuk soal hasil suntingan atau model lokal, tanpa kegagalan struktur/skor); nama penelaah adalah catatan yang diisi pengguna, bukan akun atau pengesahan lembaga eksternal.

TWK tambahan versi lama memakai 80 variasi dari 20 kerangka. Versi ini menggantinya dengan 40 soal yang berbeda beserta alasan spesifik tiap pengecoh.

TKP memakai **bank kasus baru** (lihat bagian berikutnya): satu butir = satu skenario. Keenam kompetensi sudah punya berkas di data/tkp-kasus/ (144 kasus) dan memakai kasus baru; kerangka lama (18 konteks dengan empat kondisi keputusan, lib/bank/cases.ts) otomatis tidak dipakai untuk kompetensi yang berkasnya terisi. Skor 26 contoh panduan TKP, stem, opsi, dan alasannya dikoreksi akademik lewat data/tkp-ref-koreksi.json (diterapkan saat `npm run references`; catatan koreksi hanya ada di data/reference-import-report.json, tidak tampil di aplikasi). Skor kasus orisinal merupakan rubrik latihan yang perlu telaah, bukan kunci resmi BKN.

### Bank TKP baru (data/tkp-kasus/)

- **Satu berkas JSON per kompetensi:** pelayanan-publik, jejaring-kerja, sosial-budaya, tik, profesionalisme, anti-radikalisme. Berkas berisi larik kasus; larik kosong `[]` berarti kompetensi itu belum punya kasus baru. Bentuk satu kasus (tipe `TkpKasus` di lib/bank/tkp-kasus.ts): id, skenario, topic, subtopic, pola, peran, kewenangan, penentu, tempat, keputusan, bloom, difficulty, difficultyReason, stem, options (lima: text, score, reason, tag {pembeda, pengecoh}), answer, explanation, tip, source; `konteks` opsional. Nilai pola, peran, kewenangan, tempat, keputusan, dan pembeda dibatasi daftar di lib/bank/tkp-kasus.ts.
- **Aturan skor:** skor lima opsi permutasi 1–5 dan `answer` = indeks opsi bernilai 5 (diperiksa juga oleh validator paket, lib/validate.ts). Tag pengecoh mengikuti tabel skor (SKOR_TAG di scripts/tkp-checks.ts): satu tag = satu skor.
- **Menambah kompetensi:** isi berkas kompetensinya (ganti `[]`), lalu jalankan `npx tsx scripts/tkp-checks.ts`, `npm run verify`, dan `npm run verify:quality`. Kerangka lama untuk kompetensi itu otomatis berhenti dipakai begitu berkasnya berisi kasus (lib/bank/index.ts menyaring menurut topic); tidak ada daftar lain yang perlu diubah. Berkas dengan nama lain harus didaftarkan di `TKP_KASUS_BERKAS`; pemeriksaan gagal bila ada berkas JSON yang belum terdaftar.
- **Generator:** skenario tidak pernah berulang dalam paket maupun antarpaket (bila "boleh ulang" mati) dan tidak ada fallback duplikat; bila persediaan sel topik × kesulitan kurang, pembuatan paket berhenti dengan pesan kuota. Batas sebaran per paket: pola paling banyak 15%, keputusan 20%, peran 25%, tempat 20% dari jumlah soal TKP (batas lunak; seri diundi per seed). Paket tunggal, atau paket yang boleh mengulang soal, memilih kasus satu per satu dengan penalti sebaran. Bila soal tidak boleh berulang antarpaket dan paketnya lebih dari satu, soal TWK dan TKP dari bank dibagi ke semua paket sekaligus (lib/bagi.ts): anggota kelompok eksklusif TWK disebar ke paket berbeda lebih dulu, sisa slot tiap sel (topik × kesulitan) diisi, lalu kasus TKP dipertukarkan antarpaket di dalam selnya sampai batas sebaran terpenuhi di semua paket. Dengan begitu paket terakhir tidak lagi menerima sisa persediaan (dulu TWK 5 paket gagal pada 51 dari 100 seed dan sebaran TKP dilanggar di paket ke-5). Diuji di scripts/tkp-checks.ts (5 paket, 24 seed) dan scripts/twk-checks.ts (4 dan 5 paket, 60 seed). Pemilihan TIU tidak berubah.
- **Pemeriksaan (scripts/tkp-checks.ts, bagian dari verify:quality):** skor dan tag, kunci terpanjang paling banyak 20% per kompetensi, rasio panjang opsi paling besar 1,3, kunci dalam ±20% rata-rata panjang opsi, peringkat panjang kunci dan posisi kunci A–E masing-masing 15–25% per kompetensi (mulai 20 kasus), stem 60–90 kata, alasan tidak identik lintas kasus, tanpa frasa sisa kerangka lama atau sisipan panduan, level Bloom di teks sama dengan `bloom`, serta skenario unik dan sebaran per paket hasil generate pada beberapa seed.

TIU menggunakan pengecoh dari salah prioritas operasi, salah dasar persentase, bobot rata-rata, salah jalur deret, pembalikan hubungan logika, dan perubahan fitur gambar. Beberapa keluarga sederhana hanya tersedia pada tingkat yang sesuai; label sulit tidak diberikan hanya karena angka atau narasi lebih panjang.

Kesulitan memakai **mudah / sedang / sulit**, dengan alasan kompleksitas pada setiap soal. Bloom dicatat terpisah. Input lama HOTS dinormalisasi menjadi sulit; ini tidak menyatakan bahwa setiap soal tersebut telah memenuhi tuntutan analisis tinggi.

Pada SKD, rasio 30 TWK : 35 TIU : 45 TKP diskalakan sesuai jumlah yang diminta. Durasi bawaan 100 menit. Baseline berasal dari riset pengguna dengan acuan aturan 2024, bukan penetapan aturan resmi CPNS 2027.

## Pemeriksaan mutu

- Validasi struktur, lima opsi berbeda, satu kunci terbaik, dan rentang skor.
- TWK/TIU: kunci 5, pengecoh 0. TKP: skor lima respons permutasi 1–5; satu-satunya skor 5 adalah kunci.
- Ekspresi numerik dihitung dengan parser tanpa eval.
- Silogisme diperiksa dengan enumerasi tabel kebenaran.
- Susunan dan posisi (linear, melingkar, baris-kolom) diperiksa brute force: kunci benar pada semua susunan yang memenuhi petunjuk; peringkat dan jadwal diperiksa dari seluruh permutasi yang memenuhi batasan.
- Rute dihitung ulang dari graf; kombinasi biaya dan pernyataan harga diperiksa dari model.
- Kecukupan data mengevaluasi seluruh pasangan dalam domain bilangan yang dinyatakan.
- Figural diperiksa dari rotasi, jumlah titik, warna, perubahan bentuk, atau hubungan ciri kelompok.
- Checksum konten mendeteksi stimulus, pembahasan, atau model yang berubah terpisah dari bukti awal. Ini pemeriksaan konsistensi, bukan tanda tangan keamanan.
- Butir bank dicocokkan dengan sumber; analogi kata dan penilaian argumen tetap membutuhkan pemeriksaan bahasa/substansi.
- Pemeriksaan mutu menandai panjang kunci, pengecoh dengan klaim mutlak, kumpulan opsi berulang, dan kemiripan teks. Penanda adalah heuristik untuk ditinjau.

Hasil solver membuktikan model yang dituliskan, bukan seluruh penafsiran bahasa alami. **Generator tidak memberi status disetujui; pemeriksaan substansi dilakukan pengguna.**

**data/benchmark.json** berisi 12 contoh acuan regresi dengan kunci dan pembahasan eksplisit. Contoh tersebut menunggu telaah ahli materi; tidak diberi klaim sebagai standar akademik yang sudah disahkan.

## Uji peserta dan statistik

- **Uji di perangkat ini:** mencatat pilihan dan waktu tiap soal, lalu menyimpan sesi selesai ke IndexedDB.
- **Berkas uji HTML:** penyusun mengunduh soal paket (bila fitur kurasi dihidupkan: soal yang disetujui) untuk dibagikan kepada peserta. Berkas tidak menyertakan kunci, poin, atau pembahasan. Peserta mengunduh hasil JSON dan menyerahkannya kepada penyusun.
- **Impor hasil JSON:** mendukung satu atau beberapa berkas, objek sesi, array sesi, atau berkas dengan properti sessions. ID sesi yang sudah ada tidak dihitung ulang.
- Respons dipadankan dengan ID soal, revisi, dan checksum stimulus/kunci. Respons versi lama tetap tersimpan, tetapi tidak dicampur ke analisis soal yang berubah.
- Statistik: N, frekuensi A–E, jawaban kosong, proporsi benar/terbaik, rerata poin, rerata waktu, pengecoh yang jarang dipilih, dan korelasi skor soal dengan total soal lain.
- Jawaban kosong diberi 0 poin. TWK/TIU memakai proporsi benar; TKP memakai distribusi poin, bukan klasifikasi benar/salah saja.
- Label empiris TWK/TIU baru ditampilkan pada ≥30 respons: proporsi benar ≥0,80 mudah, 0,40–0,79 sedang, <0,40 sulit. Batas ini adalah aturan awal proyek, bukan keputusan psikometrik final.
- Daya pembeda hanya dihitung pada ≥30 sesi lengkap yang cocok dengan isi seluruh soal pembanding; nilai kosong jika variasi skor tidak tersedia.

Tidak ada data peserta buatan pada dashboard. Fixture sintetis hanya dipakai oleh script pengujian dan tidak dimasukkan ke IndexedDB pengguna.

Pengumpulan hasil belum memakai basis data bersama atau tautan akun peserta. Vercel menyediakan aplikasi, sementara perpindahan hasil antarperangkat dilakukan melalui berkas.

## Ekspor

PDF dan Word: naskah tanpa kunci, kunci saja, atau soal + pembahasan. Pilihan awal **Satu file PDF/Word** langsung mengunduh dokumen; bila memilih semua paket, setiap paket dimulai pada halaman baru dalam satu berkas. **ZIP per paket** tersedia untuk lebih dari satu paket. Label "DRAF KURASI" hanya dicetak bila fitur kurasi dihidupkan. Gambar figural disertakan sebagai gambar di dokumen.

PDF, PNG, Word biasa, dan Word SiAdu tidak mencetak catatan **Sumber:**. Metadata sumber tetap tersedia di editor, CSV, JSON, dan cadangan. Panah prosa dan notasi lama `->` digambar sebagai simbol panah; rumus bertanda tebal, coret, dan warna mempertahankan gayanya di layar dan hasil dokumen. Periksa regresinya dengan `npm run verify:export-format` dan `node scripts/browser-export-qc.mjs` pada server yang sudah dibangun.

CSV: soal, opsi, skor, pembahasan, alasan, sumber, status, revisi, penelaah, catatan, alasan kesulitan, rubrik, dan stimulus. JSON: data terstruktur beserta bukti model. CSV dan JSON menyertakan kunci; gunakan naskah PDF/Word atau berkas uji HTML untuk peserta.

Ekspor memuat semua soal paket (kecuali yang ditandai dikeluarkan pada workspace lama), bukan otomatis seluruh jumlah blueprint; setelah mengganti atau menyunting soal, komposisi aktual dapat diperiksa di Hasil paket. Kolom status, revisi, penelaah, dan catatan kurasi pada CSV tetap ada (berisi data lama atau nilai bawaan).

## Ambil soal satuan atau terpilih

Untuk tim akademik yang hanya butuh satu atau beberapa soal, tanpa membuat ekspor paket. Panel **Ambil soal** ada di Hasil paket, di atas kartu soal.

- **Salin** (menu): soal (pertanyaan, tabel, gambar stimulus), pilihan A sampai E, jawaban (TKP: skor tiap pilihan), pembahasan beserta alasan tiap pilihan, atau semua. Hasilnya langsung bisa ditempel ke Word atau Google Docs: `text/html` dengan gambar PNG tertanam (gambar SVG dirasterkan di browser) dan `text/plain` sebagai cadangan.
- **Salin gambar:** tombol kecil di bawah gambar stimulus dan di bawah tiap gambar pilihan menyalin gambar itu sebagai `image/png`.
- **Unduh PNG** dan **Unduh PDF** untuk soal yang sedang dibuka. Kotak **Sertakan kunci & pembahasan** menentukan isinya. Huruf, tata letak TWK/TIU/TKP, dan gambar figural sama dengan PDF ekspor paket (satu model tata letak di `lib/export.ts` dilukis oleh PDF dan PNG). Label draf pada soal yang belum disetujui hanya dicetak bila fitur kurasi dihidupkan.
- **Pilih beberapa soal:** baris di antrean menjadi kotak centang. **Pilih semua** mengikuti filter daftar dan melewati soal yang dikeluarkan; pilihan bertahan saat filter diganti. Aksinya **Ekspor PDF** (satu berkas), **Ekspor PNG** (satu PNG per soal, dibungkus ZIP bila lebih dari satu), dan **Salin terpilih**. Urutan mengikuti paket dan nomor soal tidak diubah. Kotak centang yang sama dipakai oleh **Ganti nomor terpilih**.

Hasil salin dan unduh diumumkan lewat toast. Salinan kaya memakai Async Clipboard API (`ClipboardItem`), yang butuh HTTPS atau localhost. Bila browser tidak mendukung atau menolak akses clipboard, yang tersalin hanya teks dan toast memberi tahu; tombol salin gambar menampilkan galat dan menyarankan Unduh PNG. Pengujian UI dilakukan di Edge (Chromium); Chrome memakai mesin yang sama. Safari dan Firefox belum diuji di sini.

## Batas, CLI, dan API

Maksimal 50 paket, 200 soal per paket, 4.000 soal per proses. Persediaan per materi/kesulitan dapat membatasi lebih rendah. Analogi dua kata mempunyai 10 pasangan; pola berparameter lain juga tidak dijanjikan tak terbatas.

~~~powershell
npm run generate -- --mode SKD --paket 1 --seed LATIHAN-01 --out output
npm run generate -- --mode TIU --soal 35 --paket 5 --seed TIU-01
npm run generate -- --mode TKP --paket 5 --boleh-ulang
npm run generate -- --chapter map-14=15 --chapter map-20=5 --chapter map-54=10 --seed LATIHAN-02
~~~

CLI menulis paket.json dan validasi.json sebagai bahan paket. PDF/Word dibuat di browser.

GET /api/generate mengembalikan metadata. POST menerima pengaturan JSON, dengan batas 1.000 soal per permintaan:

~~~json
{
  "mode": "TIU",
  "count": 20,
  "packages": 1,
  "seed": "TIU-01",
  "difficulty": "campuran",
  "topics": ["Numerik"],
  "subtopics": [],
  "uniqueAcross": true,
  "composition": { "mudah": 25, "sedang": 50, "sulit": 25 }
}
~~~

Filter submateri memakai format Materi::Submateri, misalnya Figural::Matriks 3 × 3. Kuota eksplisit dapat dikirim sebagai blueprint berisi baris subtest, topic, difficulty, dan count. Jumlahnya harus sesuai distribusi subtes; kekurangan stok menghasilkan error 400.

## Pengujian dan sumber

**npm run verify** menguji determinisme, rasio, filter, stok, duplikasi, dan setiap keluarga TIU pada beberapa seed serta tingkat yang tersedia. Di dalamnya `scripts/replace-checks.ts` memeriksa Ganti nomor terpilih (tanpa duplikat dalam paket dan antarpengganti, chapter dan tingkat sama, nomor tetap, stok habis dilaporkan, hasil lolos cadangan) serta cakupan ekspor, judul, dan uji peserta saat kurasi dimatikan; `scripts/take-checks.ts` memeriksa bahwa PDF, Word, dan PNG tidak mencetak label draf saat kurasi dimatikan, dan mencetaknya bila dihidupkan.

**npm run verify:quality** menguji contoh acuan, kuota eksplisit, suntingan dan pembatalan persetujuan, ekspor, cadangan, pencocokan revisi peserta, statistik, dan petunjuk panjang kunci. Laporan ditulis ke test-results/quality-report-v2.json. Pemeriksaan sistemik (revisi akademik, tahap 1) juga dijalankan di sini: tidak ada alasan opsi generik di bank maupun paket hasil generate; tidak ada sisa catatan penyusunan ("Kesulitan Kesulitan", "Contoh Soal", "Level Bloom", "Tips & Trik", "Cara cepat") di pembahasan dan alasan TWK/TKP; alasan per opsi TIU hanya dipertahankan untuk silogisme dan analogi verbal; semua soal TIU lain apa pun asalnya (pola, bank, contoh diterima, profil tryout-2027) memakai pembahasan saja, dan opsi tanpa alasan dilewati di tampilan, PDF, Word, PNG, dan salinan. Catatan jujur: alasan silogisme belum spesifik, empat pengecohnya masih satu kalimat yang sama, dan akan ditulis ulang pada tahap 4; aturan ini hanya memastikan alasan lain tidak ditampilkan. Posisi kunci TWK dan TIU per paket merata (tiap huruf antara floor(n/5)−2 dan ceil(n/5)+2 pada beberapa seed). Soal yang opsinya tidak diacak: contoh diterima, soal model lokal, kategori kecukupan data TIU (urutan baku acuan 2027, juga pada profil tryout-2027), dan soal dengan opsi ordinal ("Sila pertama" sampai "Sila kelima", disusun menurut urutan ordinal); butir-butir itu dihitung sebagai posisi tetap saat menyeimbangkan kunci. Pada soal referensi yang diacak, hanya rujukan opsi eksplisit di pembahasan ("Opsi B", "pilihan A dan C", "(B)", butir "B.") yang dipetakan ulang; singkatan nama seperti "R.A. Kartini" tidak berubah. Laporan juga memuat dua daftar peringatan yang tidak menggagalkan pemeriksaan: pembahasan soal yang diacak yang menyebut huruf atau urutan opsi, dan tips yang terbaca sebagai rumus jawaban mutlak.

## Pembaruan variasi dan notasi matematika

Tambahan 42 model memuat 64 kasus baru dengan pilihan dan alasan tersendiri: 24 TWK dan 40 TKP. Cakupan baru meliputi atribusi karya, indikator kinerja, solidaritas lintas wilayah, serah terima, informasi biaya, akses layanan, konflik definisi data, kebutuhan budaya, izin berkas, verifikasi konten, serta pembedaan kritik dan kekerasan. Kondisi lanjutan pada model baru dapat mengganti seluruh pilihan. Model yang belum dipakai diprioritaskan dalam paket; riwayat paket juga dipakai untuk mengurangi pengulangan keluarga. Jumlah kombinasi tetap terbatas dan bukan ukuran kualitas psikometrik; status awal tetap draf untuk kurasi.

Matriks Deret ditampilkan tanpa header. Impor lama yang menyimpan baris angka pertama sebagai header dinormalisasi saat penyajian, termasuk angka negatif, tanpa mengubah isi sumber atau bukti validasinya. Tabel lain tetap memiliki header. Generator tidak lagi memilih pola figural garis bebas `analogi-garis` dan `ketidaksamaan-garis`; pembaca cadangan lama tetap dapat menampilkannya. Gunakan Ganti soal atau buat paket baru untuk mengganti butir lama tersebut.

Rumus memakai renderer LaTeX lokal MathJax SVG tanpa CDN. Notasi eksplisit `\( ... \)` dan `\[ ... \]` didukung pada soal, pilihan, pembahasan, dan tabel; operasi aritmetika lama, pecahan dari Word, serta pangkat ²/³ dinormalisasi saat ditampilkan. Teks sumber dan bukti hitung tetap utuh. PDF, PNG, Word, salinan kaya, serta HTML peserta menyertakan rumus yang sudah dirender. Rumus di Word dan clipboard berupa gambar; teks biasa/CSV menyertakan notasi LaTeX, sedangkan JSON cadangan mempertahankan sumber aslinya. Rumus khusus yang belum terdeteksi otomatis dapat diberi pembatas LaTeX lewat Sunting soal.

`npm run verify:presentation` menguji konversi rumus, enam matriks sumber, pengamanan HTML, keragaman model satu paket, dan tidak munculnya figural garis. `scripts/browser-presentation.mjs` memeriksa tampilan desktop/mobile, salin, ekspor rumus dan matriks, serta HTML peserta offline. Renderer mengikuti [dokumentasi SVG MathJax 3.2](https://docs.mathjax.org/en/v3.2/options/output/svg.html); dependensi dipin agar hasil tidak berubah oleh CDN.

## Format pembahasan TIU (revisi akademik tahap 4a)

Pembahasan TIU mengikuti Panduan Produksi Soal TIU JadiASN dan Contoh Soal TIU SKD 2027. Datanya tetap satu string `explanation`, satu blok per baris (lib/explanation.ts): sub-judul baku (`Diketahui:`, `Ditanyakan:`, `Rumus Dasar:`, `Penyelesaian:`, `Kesimpulan:`, `Rumus Cepat:`), butir `• teks` dan `1. teks`, tabel `| a | b |` (baris `|---|---|` setelah header; tanpa baris itu tabel tanpa header), persamaan satu baris `\[ ... \]` (bertingkat lewat `aligned` sehingga tanda "=" rata kiri), dan baris kosong sebagai jarak. Pembahasan tanpa penanda (TWK, TKP, soal lama) tampil dan diekspor seperti sebelumnya. Layar, PDF, PNG, Word, salinan teks, dan CSV memakai struktur yang sama; salinan teks dan CSV menerjemahkan LaTeX menjadi teks terbaca ("3/5 + 1/5 − 7/10", tabel bersekat " | "). Soal TIU di PDF, PNG, dan Word memuat baris **Pembahasan:** setelah **Jawaban**.

Keluarga yang sudah memakai format ini: Berhitung (`hitung`), Operasi pecahan (`pecahan`, termasuk tabel pecahan istimewa bila soal memakainya), Pola bilangan tabel (`tabel`), dan Kecukupan data (`data`), juga baris profil tryout 24, 27, dan 47 yang memakai keluarga itu. Opsi berhitung dan pecahan seragam bentuk (bilangan bulat semua atau desimal semua dengan jumlah desimal sama). Keluarga lain belum diubah. Pemeriksaannya ada di scripts/tiu-format-checks.ts (`npx tsx scripts/tiu-format-checks.ts`) dan ikut `npm run verify:quality`.

**Perubahan seed:** paket profil tryout dari seed lama berubah pada soal kecukupan data (baris 27 tidak lagi mengulang pernyataan (1) sebagai (2) pada pola jumlah) dan soal pecahan baris 24 (opsi seragam desimal) bila memakai sumber variasi baru; rekaman seed di `TRYOUT_SEED_SNAPSHOT` (scripts/quality-verify.ts) sudah diperbarui untuk profil variasi, sedangkan pemilihan butir profil contoh diterima tidak berubah (hanya teks butir yang direvisi yang berbeda; lihat QA akhir 4c–4e di bawah). Keluarga `data` pada generator bebas juga tidak lagi menghasilkan pernyataan (1) dan (2) yang sama.

**Tahap 4b:** soal cerita numerik (`cerita-hitung`: JKW, VDW, rata-rata dasar/gabungan, diskon dan persentase bertahap Haji Miu, perbandingan senilai/berbalik, pembagian rasio, dan lima subjenis polemik proyek dengan rumus WOWO) dan verbal analitis (`posisi`, `peringkat`, `jadwal`, `kategori` bentuk orang-kegiatan dan objek-tempat) kini mengikuti panduan. Informasi di soal analitis diberi nomor; pembahasan menerapkan informasi itu satu per satu (lib/tiu-analitis.ts) dan hasilnya diperiksa ulang terhadap solver. Penanda tambahan: `> teks` (kotak rumus) dan `{kunci}` (huruf kunci jawaban, diisi dari kunci saat tampil dan ekspor, sehingga tetap benar setelah opsi diacak). Soal `posisi` dari pola berubah bentuk soal dan pembahasannya, sehingga paket profil tryout dari seed lama yang memakai pola itu sebagai pengganti contoh diterima ikut berubah.

**Tahap 4c:** pembahasan deret angka (`deret` satu dan dua towew, `fibonacci`, `tiga-jalur`, `selang-seling`, dan baris profil tryout 39) mengikuti panduan. Deret yang memakai towew diawali konsep towew (angka dengan panah ↑ ↓, tiga panah pertama dilingkari, tabel 1/2/3 towew, dan "↑ ↓ ↑ artinya 2 towew"); lalu "Pola yang terlihat:" berupa angka dengan panah melengkung berlabel selisih, rasio, atau operasi dan suku jawaban berwarna, panah turun "1+1" untuk Fibonacci, dan pola Campuran (+a, −b bergantian) untuk selang-seling. Deret tidak memakai "Rumus Cepat" karena contoh panduan tidak memakainya. Diagram disimpan sebagai satu baris `@deret {JSON}` (lib/chain.ts; penyusun kalimat di lib/tiu-deret.ts) dan digambar sebagai SVG yang sama di layar, PDF, PNG, Word (gambar), dan salinan (satu gambar per diagram); teks polos ("a →(+2) b") dipakai di CSV dan salinan teks. Generator menghitung kunci dan pola, lalu menolak soal bila arah suku tidak cocok dengan jumlah towew atau jawaban berbeda dari langkah terakhir. Contoh panduan yang keliru tidak disalin (PDF 70–71: U7 tertulis 55 padahal (7×10)−1 = 69). Baris 18 profil tryout kini memakai stem bernomor dan pembahasan per informasi seperti 4b. Cek ulang pola, rantai panah, dan penolakan pembahasan yang dirusak ada di scripts/tiu-format-checks.ts; `TRYOUT_SEED_SNAPSHOT` profil variasi diperbarui karena stem baris 18 dan angka deret sulit berubah.

**Pengecoh dan opsi soal cerita:** pengecoh deret dan soal cerita numerik hanya dari kesalahan konsep (selisih atau rasio salah, melompat satu suku, larik keliru, operasi tertukar, satuan tidak dikonversi, rumus tertukar, bobot tertukar). Nilainya bilangan bulat positif, berskala sama dengan kunci, dan berada dalam rentang logis subjenis (mis. rata-rata gabungan di antara kedua rata-rata kelompok, tambahan hari tidak melebihi hari rencana); tidak ada pengisi aritmetika. Sumber tiap pengecoh dicatat di `proof.distractors` (tidak ditampilkan; deret memakai kode sumber yang dihitung ulang oleh pemeriksa). Opsi soal cerita memakai satuan dan titik ribuan seperti stem ("Rp60.000", "120 km", "2 pekerja"), dan stem rupiah memakai titik ribuan. Soal objek-tempat menulis "hanya tersedia di Toko A, B, dan C" supaya tafsir inklusif dan eksklusif sama-sama menghasilkan satu toko; pemeriksa menguji kedua tafsir dengan brute force. Penanda `{kunci}` pada `explanation` yang tersimpan mentah di berkas JSON dan cadangan memang disengaja: huruf kunci baru diisi saat soal ditampilkan atau diekspor, sehingga tetap benar setelah opsi diacak atau disunting.

**Tahap 4d (figural):** pembahasan Figural Analogi, Ketidaksamaan, Serial, dan Matriks 3 × 3 kini berdiagram beranotasi seperti panduan (PDF 158–178): pasangan A → B dan C → jawaban dengan panah biru berlabel hubungan; ketidaksamaan dengan kotak biru/merah pada bagian yang berbeda (putar-putar), label jumlah bangun hitam (paritas) atau "n sisi" berwarna per pasangan; serial dengan kotak bernomor, panah berlabel tiap aturan, dan angka di sudut untuk soal jumlah; matriks dengan lingkaran merah pada bagian yang dibahas, angka latar biru muda untuk soal jumlah, dan baris "kotak + kotak = kotak" untuk tumpukan. Kotak jawaban berbingkai hijau dengan tag kuning "Sesuai dengan gambar pada opsi {kunci}", lalu "Jadi, jawaban yang benar adalah {kunci}." Tidak ada ulasan per opsi. Diagram disimpan sebagai baris `@gambar {JSON}` yang memuat gambar-gambarnya sendiri (lib/figural/annotate.ts; penyusun kalimat di lib/figural/pembahasan.ts), dan digambar sebagai SVG yang sama di layar, PDF, PNG, Word (gambar), serta salinan (satu gambar per diagram, teks polos di CSV). Kotak yang berupa gambar opsi bertanda `opt`: huruf dan urutannya diisi dari susunan opsi yang tampil, sehingga tetap benar setelah opsi diacak. Contoh panduan yang keliru tidak disalin (PDF 172: teks menyebut bulan sabit 0, 2, 4, 6 dan jawaban 8 bulan, padahal gambarnya 0, 1, 2, 3 dan jawaban 4): semua angka dan label dihitung ulang dari gambar soal, dan pemeriksa di scripts/tiu-format-checks.ts mencocokkan setiap kotak, label, angka, lingkaran, dan tag dengan data soal serta menolak diagram yang dirusak.

**Tahap 4e (rute, silogisme, analogi verbal):** *Rute dan Jalur* (`rute`) kini berupa jaringan berlapis dengan kemungkinan sisi dua arah ("saling terhubung", dua baris pada tabel); rute dihitung sebagai rute sederhana (simpul tidak boleh dilewati dua kali) dengan penelusuran, pembahasan mendaftar semua rute ("A – B – D – I – J", lalu "Jadi, terdapat N rute yang dapat dilewati.") dan menggambar grafnya sebagai baris `@graf {JSON}` (lib/graph.ts; simpul masuk hijau, simpul keluar kuning, sisi dua arah berpanah ganda). Contoh panduan PDF 48 menggambar sisi D–E satu arah padahal daftar rutenya memakai kedua arah, sehingga tidak ditiru. *Silogisme* (lib/tiu-logika.ts) mengikuti PDF 18–26: dua premis (Modus Ponens, Modus Tollens, Silogisme, TDS), tiga premis (Silogisme + Modus Ponens atau Tollens, Silogisme dua kali, TDS), ekuivalensi (hukum implikasi atau kontraposisi), dan bentuk implikasi (konvers, invers, kontraposisi); pembahasan berbentuk "Premis n", definisi p/q/r, langkah dengan rumus, "Kesimpulan", "Jawaban". Ulasan tiap opsi (keputusan akademik F.1) memakai status dari mesin logika: "Pasti mengikuti premis", "Bertentangan dengan premis", "Belum dapat dipastikan" (atau "Tepat" bagi TDS) dengan alasannya. Soal kuantor panduan tidak dibangkitkan: PDF 31–32 (Semua + Sebagian) dan PDF 35–36 (Sebagian + Sebagian) menyimpulkan "Sebagian … " yang secara logika tidak mengikuti premis. *Analogi verbal* (lib/tiu-analogi.ts) berbentuk "Kata 1 : Kata 2 = … : …" dengan pasangan kata sebagai opsi (PDF 16–17); jenis hubungan berasal dari katalog sembilan jenis, pengecoh adalah pasangan berjenis hubungan lain atau berarah terbalik, dan ulasan tiap opsi menyebut jenis, arah, "sepadan" atau "tidak sepadan", dan alasannya. Ulasan opsi memakai lambang biasa (¬, →) sehingga terbaca sama di layar, CSV, Word, dan salinan; paragraf pembahasan yang memuat rumus `\( \)` dianggap terstruktur sehingga rumusnya ikut diterjemahkan pada salinan teks dan CSV. Tingkat "sulit" figural kini memuat porsi HOTS (tiga dari sepuluh seed): serial empat aturan, analogi tiga perubahan, matriks jumlah ganda dan tumpuk saling menghilangkan.

### Silogisme menurut Blueprint akademik (28 Okt 2026, disesuaikan 29 Okt)

Generator silogisme (`lib/tiu-logika.ts`, dengan `lib/silo-spec.ts`, `lib/silo-frames.ts`, `lib/silo-lang.ts`, dan contoh blueprint di `lib/silo-contoh.ts`) mengikuti *Blueprint Silogisme Tanpa Logika Kuantor* (tanpa kuantor, tanpa "jika-maka"). Rangkaian kerjanya: pola formal (katalog bertanda) → premis berupa prosa → kunci dan pengecoh dihitung dengan tabel kebenaran (`lib/solver.ts`) → pembahasan menurut format blueprint dan panduan. Pada premis tidak ada kuantor, titik dua, penghubung bersyarat (jika, apabila, bila, maka), maupun penanda sebab-akibat; hubungan disampaikan lewat klausa pewatas ("Rina yang terdaftar sebagai peserta memperoleh hak memilih sesi"), "dengan/tanpa", predikat kategori, dan (narasi) predikat hak di depan. Narasi juga tanpa koma, kecuali satu koma sesudah pembuka "Dalam ketentuan …" pada kalimat predikat hak di depan.

- **Penempatan.** Pada mapping tryout 2027: baris 13 = *3 Premis*, baris 14 = *2 Premis - Narasi*, baris 15 = *3 Premis - Narasi* (`lib/tryout-patterns.ts`, pembangkit pada pengacak turunan `ROW_DRAWS`). Chapter *2 Premis* (Biasa) tidak ada pada mapping; ia keluar lewat pola umum `silogisme` ("Silogisme naratif" pada **Penyusunan pola**, `lib/tiu.ts`, tingkat sedang memuat 2 Premis dasar, 2 Premis - Narasi, dan bentuk implikasi; tingkat sulit memuat 2 Premis dengan ekuivalensi, 3 Premis, dan 3 Premis - Narasi). Bentuk implikasi (konvers, invers, kontraposisi; `lib/tiu-implikasi.ts`) bukan bagian blueprint dan tidak berubah.
- **Contoh blueprint dipakai lebih dahulu (Narasi).** Kedua chapter Narasi memakai lebih dahulu 19 contoh tulisan tim akademik (Bagian B, Contoh 55–73: 8 dua premis, 11 tiga premis) sebagai butir jadi, lengkap dengan pembahasan dan analisis opsi dari blueprint; format diubah seperlunya ke penanda aplikasi (rumus `\( \)`, huruf opsi `{opsi:N}`), isinya tidak diubah. Urutan pemakaian diacak menurut seed (pengacak tersendiri) dan contoh ke-n dipakai bila n lebih kecil daripada jumlah contoh; sesudahnya pembangkit mengisi kekurangan (mis. lima paket tryout memerlukan 10 soal dua premis dari 8 contoh, jadi 2 soal dari pembangkit; baris 15 memerlukan 10 dari 11 contoh). Berlaku pada profil variasi, penggantian nomor, dan latihan bebas (silogisme naratif). Profil **contoh diterima** tidak berubah: baris 13–15 tetap mengambil contoh diterima dari berkas tryout lebih dahulu. Dua contoh bersusunan terbalik (55 dan 65) membawa padanan kondisi-lebih-dahulu untuk batas produksi 20%.
- **Kunci dan pengecoh dihitung, bukan ditulis tangan.** Setiap opsi diuji dengan tabel kebenaran terhadap premis: tepat satu opsi sah, tidak ada opsi lain yang setara dengan kunci, opsi "Tidak dapat disimpulkan" hanya benar bila tidak ada kesimpulan sah, dan pada kunci pasti tiap premis diperlukan (kunci tidak lagi pasti bila satu premis dibuang). Pada TDS, pernyataan yang ditanyakan dan negasinya sama-sama mungkin. Tiap pengecoh dipetakan ke satu dari lima jenis kesalahan blueprint: *Konvers dan invers*, *Negasi dan operator*, *Syarat perlu dan cukup*, *Kepastian tanpa dukungan*, *Informasi tambahan*; jenis itu tersimpan di `proof.model.errors`. Alasan opsi hanya ada pada Silogisme Narasi (pada analisis opsi); alasannya singkat, meniru redaksi analisis contoh blueprint, dan berbeda menurut jenis kesalahan (mis. "Pernyataan ini berlawanan dengan keadaan yang dipastikan oleh premis dan hasil penerapan modus.", "Arah hubungan dibalik. …", "Opsi menyatakan keadaan tambahan …"); kunci dibuka dengan "Maknanya sama dengan hasil penalaran langsung." dan TDS dengan "Nilai kebenaran pernyataan yang ditanyakan belum dapat ditetapkan.". Silogisme Biasa tidak memuat alasan opsi. Komposisi lima jenis itu diundi per soal (tidak selalu dua *Informasi tambahan* dan dua *Negasi dan operator*). Pada kunci literal semua proposisi premis sudah ditetapkan, sehingga konvers, invers, dan syarat pasti benar (menjadi kunci kedua) dan tidak dipakai; pengecohnya kebalikan literal, gabungan "dan", "tidak terjadi bersamaan", dan keadaan tambahan `t`. Kunci berupa hubungan (stem "Hubungan yang pasti mengikuti …") hanya didampingi pengecoh berupa hubungan. Sedikitnya dua pengecoh bebas dari bentuk "dan", "tidak terjadi bersamaan", dan predikat baru, dan posisi kunci menurut panjang teks diundi merata (teks kunci TDS berbunyi "Tidak dapat disimpulkan." atau varian yang menyebut premisnya, sedangkan baris `**Jawaban: …**` tetap "Tidak dapat disimpulkan"). Opsi memuat paling banyak dua kata "tidak", dan premis maupun opsi tidak memuat frasa berulang (tiga kata atau lebih; subjek dikecualikan). Stem mengikuti Bagian 5 blueprint ("Simpulan yang pasti benar berdasarkan ketentuan tersebut adalah …." untuk dua premis Biasa dan Narasi; "…berdasarkan ketiga premis tersebut…" untuk tiga premis Biasa). Silogisme Biasa memakai koma setelah keterangan pembuka ("Dalam ketentuan tersebut, …"); Narasi tanpa koma (Bagian 18 dan 24), termasuk sesudah pembuka "Dalam ketentuan …" seperti contoh blueprint.
- **Kerangka kalimat narasi.** Premis dan opsi Narasi disusun dari kerangka kalimat utuh per bentuk logika (Bagian 19: klausa pewatas, pewatas "dengan/tanpa", cakupan daftar, predikat hak di depan, fakta langsung atau melalui catatan, pilihan "atau"), bukan dari potongan frasa dengan keterangan pengisi. Sepuluh kerangka konteks (`NARASI_FRAMES`) menyediakan lima proposisi bertulisan tangan; pembuka berkonteks ("Dalam ketentuan …", "Catatan … menunjukkan …", "Menurut ketentuan …") dipakai paling banyak satu kali per soal, opsi Narasi tanpa pembuka, dan keterangan rujukan yang diulang di tiap premis ditolak (pemeriksa pengisi berulang antarpremis; frasa proposisi penghubung boleh muncul pada dua premis). Pasangan makna (menyala/padam, terbuka/tertutup, lulus/gagal) membawa batas domainnya pada predikat sehingga terbaca pada soal.
- **Pembahasan.** Urutan: kutipan premis (kalimat lengkap sesuai stem), definisi variabel positif (`p`, `q`, `r`, `s`), rumus premis, hukum (Modus Ponens, Modus Tollens, rumus/hukum Silogisme, Silogisme Disjungtif, atau "tidak masuk ke rumus silogisme manapun sehingga tidak dapat disimpulkan"), hukum ekuivalensi bila premis atau kunci bertransformasi, `**Kesimpulan: …**`, `**Jawaban: …**`; tiga premis memakai `**Langkah 1 (Premis a + b):**` dan `Kesimpulan (Premis 4)`, dengan label Premis 1–3 menurut urutan yang tampil di soal. **Silogisme Biasa berakhir di baris `**Jawaban: …**`** (blueprint Bagian 8: "format inti berakhir pada jawaban kalimat"): tanpa analisis opsi dan tanpa daftar alasan opsi. **Silogisme Narasi** menambahkan **Analisis setiap opsi** persis seperti contoh blueprint: notasi tambahan bila opsi memuat proposisi baru (`\(t\): …` dan kalimat "Notasi tambahan ini hanya memetakan isi opsi dan tidak menjadi premis soal."), lalu tiap opsi `X. teks` (teks opsi salah dicoret `~~teks~~`, kunci tidak) dan baris `→ **rumus** — alasan singkat (**kesimpulan yang dicari** atau **bukan kesimpulan yang dicari**)`. Huruf `X` tidak ditulis mati: pembahasan menyimpan penanda `{opsi:N}` (N = `Option.ref`, nomor tetap opsi yang ikut berpindah bersama opsinya) dan `explanationOf` (`lib/explanation.ts`) mengisi hurufnya serta mengurutkan butir A–E saat tampil dan ekspor, sehingga huruf tetap benar setelah opsi diacak, diseimbangkan, atau disunting. Karena analisis sudah memuat alasan tiap opsi, daftar alasan opsi di bawah pembahasan tidak diulang pada layar, PDF, Word, dan salinan (CSV tetap memuat kolom Alasan A–E, kosong pada Silogisme Biasa).
- **Format pembahasan akademik.** Teks TIU memakai Times New Roman 12 pt, judul dan kata kunci tebal, opsi salah dicoret, serta warna merah sesuai panduan pada tabel WOWO dan mnemonik TiFuS/PS/VDW. Penanda `**tebal**`, `~~coret~~`, dan `{merah:teks}` berlaku pada teks maupun rumus di layar, PDF, PNG, Word, dan salinan HTML. Word menggunakan run `bold`, `strike`, dan `color`; rumus cetak dirasterkan dengan warna run yang sama. CSV dan salinan teks polos mempertahankan isi tanpa penanda format. Label **Jawaban: X** diikuti **Pembahasan:** pada seluruh subtes, termasuk TWK/TKP.
- **Gambar acuan asli.** `data/tiu-guide-images.json` menyimpan byte asli gambar pecahan istimewa (image16), segitiga JKW (image29), dan VDW (image30) dari panduan, beserta SHA-256 dan ukuran tampil sumber. `@acuan id` merendernya pada layar dan ekspor. Diagram deret/figural tetap dibangkitkan sesuai angka dan bentuk soal, dengan pola anotasi panduan; gambar jawaban contoh tidak ditempel ke soal yang datanya berbeda.
- **Keacakan.** Seluruh keacakan lewat pengacak turunan yang diberikan; jumlah undian aliran bersama (`SHARED_DRAWS`, `ROW_DRAWS`) tidak berubah, sehingga pemilihan butir lain pada seed yang sama tidak bergeser (diperiksa dengan membandingkan sidik jari 30 seed × 3 paket sebelum dan sesudah). Hanya `TRYOUT_SEED_SNAPSHOT` profil *variasi* yang diperbarui ("silogisme blueprint akademik 28 Okt" dan penyesuaian 29 Okt); profil contoh diterima tidak berubah. Pada penyesuaian 29 Okt, perbandingan 3.585 butir sebelum dan sesudah (15 kelompok seed) menunjukkan 3.424 identik dan 161 berbeda, semuanya butir baris 13–15 atau keluarga silogisme. Pemilihan contoh blueprint memakai pengacak tersendiri (`seed|contoh-narasi|chapter`), jadi tidak menggeser butir lain.

Pemeriksa mandiri kini juga memastikan: Silogisme Biasa tanpa analisis dan tanpa alasan opsi; analisis Narasi lima opsi berhuruf benar (juga setelah opsi diacak) dengan alasan singkat menurut status tabel kebenaran; tanpa frasa pengisi berulang antarpremis; 19 contoh blueprint lolos aturan yang sama (kecuali aturan frasa pembangkit) dan terpakai lebih dahulu pada profil variasi (baris 14: 8 contoh lalu 2 dari pembangkit; baris 15: 10 dari 11 contoh) dan latihan bebas; padanan kondisi-lebih-dahulu pada Contoh 55 dan 65.

### Verbal Analitis menurut Panduan Produksi Soal TIU JadiASN (29 Okt 2026)

*Susunan & Posisi (baris tryout 18, keluarga `posisi`)* kini dibangkitkan oleh `lib/tiu-posisi.ts` (model dan pemecah di `lib/posisi-model.ts`, penalaran di `lib/posisi-deduce.ts`, bahasa di `lib/posisi-text.ts`) dengan tiga subbentuk panduan: susunan linear (berdiri, duduk, antre; kiri-kanan atau depan-belakang), duduk melingkar (kiri seseorang = kursi tepat setelahnya searah jarum jam, definisi yang sama dengan contoh akademik), dan baris-kolom (2 atau 3 kursi per baris).
- **Petunjuk berupa paragraf**, bukan daftar bernomor; nama diperkenalkan "(A, B, C, D, dan E)" atau "yaitu ..., dan ...". Kalimat bervariasi: posisi tertentu, di sebelah kiri atau kanan, di antara, dipisahkan beberapa orang, tidak di samping, berhadapan, tepat di belakang, satu baris, dan negasinya.
- **Jawaban tunggal dibuktikan brute force.** Petunjuk dipilih dari fakta yang benar pada susunan acuan, ditambah sampai kunci pertanyaan benar pada SEMUA susunan yang memenuhi petunjuk, lalu petunjuk berlebih dibuang. Susunan linear dan melingkar selalu tunggal; baris-kolom boleh menyisakan kursi yang belum pasti (tabel memuat "?", seperti contoh panduan) selama jawabannya tunggal. `proof.model` bertipe `arrangement` menyimpan petunjuk dan fakta tiap opsi sebagai data, sehingga `solveModel` dapat memeriksa ulang kunci.
- **Pertanyaan:** siapa di posisi tertentu, posisi seseorang, siapa di samping atau berhadapan, siapa satu baris atau tepat di belakang, di antara siapa seseorang duduk, pernyataan yang pasti benar, dan susunan lengkap.
- **Bloom dan kesulitan diturunkan dari kebutuhan penalaran** (tabel panduan: C4–C6, Sedang–HOTS): sedang = petunjuk berantai tanpa menguji andaian (C4); sulit = perlu menguji kemungkinan yang gugur atau menilai pernyataan (C5) atau merekonstruksi susunan lengkap (C6), atau memuat tujuh petunjuk atau lebih. Kompleksitas berasal dari hubungan antarpetunjuk, bukan dari jumlah tokoh atau redaksi berbelit.
- **Pembahasan mengalir:** petunjuk pasti lebih dahulu, "sehingga ...", pencoretan kemungkinan yang gugur beserta alasannya ("Jika X berada di ..., maka ... Jadi X tidak berada di ..."), susunan akhir, penutup "Jadi, jawaban yang benar adalah {kunci}.", lalu tabel posisi bernama tebal (melingkar: nomor kursi searah jarum jam; baris-kolom: Baris x Kursi Kiri/Kanan). Hanya langkah yang menjadi dasar penempatan yang ditampilkan; tidak ada pola "Informasi n: ... Akibatnya, ...". Peringkat dan jadwal belum diubah dan tetap memakai informasi bernomor.

*Memperkuat/Memperlemah Argumen (baris tryout 17, keluarga `argumen`)* dibangkitkan oleh `lib/tiu-argumen.ts` dari 18 skenario tulisan tangan (9 sedang, 9 sulit), masing-masing berisi argumen, satu temuan penguat, satu temuan pelemah, dan empat pengecoh netral (tidak relevan, sebagian, di luar cakupan, mengulang premis). Kedua arah dari satu skenario dihitung sebagai dua butir, jadi ada 36 butir. Opsi: kunci, arah terbalik (temuan arah lawan), dan tiga dari empat pengecoh netral (satu digugurkan secara acak). Pembahasan: alasan, kesimpulan, penghubung, temuan kunci, pengecoh terkuat yang gagal, lalu penutup. `proof.model` bertipe `argument` menyimpan peran tiap opsi.
- **Profil contoh diterima tetap memakai sembilan contoh** (Andika) pada baris 17; pembangkit hanya mengisi bila contoh habis (paket keempat dan seterusnya, atau filter kesulitan yang menyisakan sedikit contoh). Pada profil variasi baris 17 kini dibangkitkan (masuk `VARY_ROWS`).
- **Lima paket x tiga butir tanpa ulang.** Butir diambil dari daftar berurutan menurut seed (tiap skenario muncul sekali sebelum arah lawannya) dan tingkat bergantian sedang/sulit, sehingga 15 butir pada lima paket memakai 15 skenario berbeda. Baris 17 pada profil tidak mengambil undian dari aliran bersama.
- **Kunci tidak selalu terpanjang** (paling banyak 25%; terhitung 16,7% dari seluruh kombinasi skenario x arah x pengecoh yang digugurkan).
- **Pemeriksaan:** `npx tsx scripts/tiu-format-checks.ts` (bagian `runAnalitisChecks`, `checkPosisi`, `checkArgumen`) memeriksa jawaban tunggal oleh pemecah, stem tanpa daftar bernomor, daftar nama memakai "dan", pembahasan tanpa "Informasi n:", penutup {kunci}, tabel akhir, kalimat penalaran terhadap pemecah, peran opsi, panjang opsi, tidak ada ulang pada lima paket, dan isolasi undian.
- **Keacakan.** `posisi:sedang` (21) dan `argumen:sulit` (2) ditambahkan ke `SHARED_DRAWS`, baris 18 (18) ke `ROW_DRAWS`, sehingga pemilihan butir lain pada seed yang sama tidak bergeser. Terhadap keadaan sebelum perubahan (40 seed: profil contoh diterima dan variasi 3 paket, TIU 2 paket, SKD 2 paket; 38.000 butir), 36.852 butir bukan analitis identik; yang berbeda hanya butir baris 17 dan 18 serta keluarga `posisi` dan `argumen`, dan pada empat paket (seed 21 SKD, 31 dan 34 TIU, 35 SKD) butir sesudah satu butir `argumen` bergeser karena pembangkit lama `argumen` (hanya 8 kombinasi) kolisi dan beralih ke keluarga `peringkat`, sedangkan pembangkit baru tidak lagi kolisi. Keempat nilai `TRYOUT_SEED_SNAPSHOT` diperbarui.

### Video pembahasan Remotion (opsional)

Di **Hasil paket → Ambil soal**, tekan **Video pembahasan**. Pilih soal yang sedang dibuka, beberapa nomor terpilih, atau seluruh paket aktif. Untuk beberapa nomor, gunakan **Pilih beberapa soal** sebelum membuka dialog video. Soal yang dikeluarkan tidak disertakan; urutan tetap mengikuti paket.

1. Pilih tempo membaca dan jeda sebelum jawaban, lalu **Siapkan pratinjau**.
2. Periksa melalui pemutar, **Lompat ke soal**, atau **Lihat tahap pembahasan**. Durasi dihitung dari panjang teks dan gambar; perubahan tempo tidak perlu menyiapkan gambar ulang.
3. Tekan **Unduh MP4**. Hasilnya satu video gabungan 1280×720, 24 fps, rasio 16:9, tanpa audio. Proses dapat dibatalkan. Setelah selesai, **Unduh ulang MP4** memakai hasil yang sama selama dialog tetap terbuka dan pengaturan tidak berubah.

Urutan video: soal → pilihan → jawaban → pembahasan → cara cepat bila tersedia. TKP menyertakan poin semua opsi sesuai urutan tersimpan. Video menggunakan isi, kunci, pembahasan, dan gambar yang sama dengan paket; tidak menulis ulang materi dengan AI. Rumus MathJax, tebal, warna, coretan, dan gambar panduan dirasterkan sebelum masuk ke komposisi Remotion. Pembahasan panjang dipaginasi, tabel tinggi dipecah per baris dengan header asli diulang. Sumber/provenance tidak dicetak. Tempo adalah waktu baca perkiraan, bukan sinkronisasi narasi.

Render MP4 berjalan di browser dengan `@remotion/web-renderer` (WebCodecs H.264), tanpa route render server atau API AI berbayar. Gunakan Chrome/Edge terbaru pada komputer; dukungan codec diperiksa sebelum tombol unduh aktif. Pratinjau tetap dapat digunakan bila codec ekspor tidak tersedia. Biarkan tab terbuka; durasi panjang dan banyak soal membutuhkan lebih banyak waktu, memori, serta ruang penyimpanan perangkat. Untuk pemeriksaan awal, gunakan satu soal atau beberapa soal. Pemilihan seluruh paket dapat menghasilkan video berdurasi berjam-jam. Tidak ada batas jumlah soal tambahan di fitur video.

Remotion dimuat hanya ketika dialog dibuka. Vercel tetap membangun aplikasi Next.js biasa (`npm run build`); tidak memerlukan Lambda, FFmpeg server, atau token layanan AI. Versi `remotion`, `@remotion/player`, dan `@remotion/web-renderer` dipatok sama di `package.json`.

**Lisensi dan privasi:** tidak ada biaya API AI, tetapi penggunaan Remotion oleh organisasi mengikuti [lisensi Remotion](https://www.remotion.pro/license), termasuk ketentuan lisensi perusahaan. Aplikasi tidak menyatakan kelayakan lisensi gratis atas nama pengguna. Jika memiliki kunci lisensi yang ditujukan untuk renderer browser, set `NEXT_PUBLIC_REMOTION_LICENSE_KEY` sebelum build (nilai ini terlihat di klien; jangan mengisinya dengan rahasia server/API lain). [Telemetri Remotion](https://www.remotion.dev/docs/telemetry) mengirim IP, origin/domain, jenis dan status render, serta kunci lisensi bila diisi; bukan isi soal atau video. ### Seed dan perbandingan variasi

Kolom **Seed** dan tombol **Acak seed** ada di bagian utama Buat paket. Tombol **Bandingkan seed & ruang variasi** membuka pratinjau menggunakan pengaturan yang sama, termasuk kuota manual. Pada Hasil paket, seed utama ditampilkan di panel unduhan; **Bandingkan seed ini** memakai pengaturan workspace tersebut.

Di halaman **Bandingkan seed**:

- Masukkan seed A/B untuk membandingkan semua paket dari dua seed. Seed serta pengaturan yang sama menghasilkan paket awal yang sama pada versi kode/bank yang sama. Penggantian atau suntingan yang dilakukan setelah generate tidak direproduksi hanya dari seed; gunakan cadangan workspace untuk mempertahankannya.
- Ringkasan membedakan isi sama, isi sama dengan opsi diacak, perubahan pembahasan, isi berubah pada pola yang sama, dan butir/kasus lain. Kunci dan skor dibandingkan bersama isi pilihan, bukan huruf jawaban semata. Tanda operasi dan desimal tetap diperhitungkan; ID, seed internal, serta nomor soal diabaikan.
- Butir identik dicocokkan lintas nomor/paket sebelum pencocokan berdasarkan model, pola, atau chapter. Satu butir A hanya boleh menjadi pasangan satu butir B. Label kesamaan pola mengikuti metadata yang tersedia, bukan penilaian otomatis atas makna atau mutu akademik.
- Buka pasangan untuk melihat soal, kunci/poin, tabel/gambar, pembahasan, serta variabel konteks, kondisi, angka, model penalaran, atau aturan figural berdampingan. Variabel yang berbeda disorot.
- **Uji 5/10/20 seed dari A** menunjukkan isi unik per seed, tambahan isi yang belum muncul sebelumnya, akumulasi isi unik, dan persentase yang juga ada pada seed A. Seed angka berjalan berurutan; seed teks memakai akhiran `-uji-2` dan seterusnya. Pengacakan pilihan tidak dihitung sebagai isi baru. Maksimal 6.000 soal per pengujian; proses dapat dihentikan di antara seed.
- **Ruang variasi** menampilkan sumber yang cocok dengan filter: jumlah kombinasi konteks × kondisi pada model lokal, stok butir bank, serta variabel pada kelompok pola TIU. Total kombinasi valid TIU belum dihitung; angka hasil uji seed hanya ukuran sampel, bukan total kapasitas atau klaim variasi tanpa batas. Larangan pengulangan dan validasi dapat mengurangi kapasitas paket.
- **Gunakan seed A/B** memindahkan pengaturan ke Buat paket. Pratinjau perbandingan tidak menimpa atau menyimpan workspace; tekan Buat paket untuk membuat hasil baru.

Verifikasi: `npm run verify:seeds` menguji determinisme, pengacakan pilihan teks/gambar, perpindahan nomor, tanda matematika, skor, kondisi lokal, pencocokan multiset, akumulasi sampel, katalog, dan filter. `node scripts/browser-seeds.mjs` menguji alur antarmuka dengan server berjalan; gunakan `SKD_BROWSER_URL`, `SKD_PLAYWRIGHT_MODULE`, dan `SKD_BROWSER_EXECUTABLE` seperti uji browser ekspor.
